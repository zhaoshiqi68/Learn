Harness Engineering：编程 Agent 的外壳是怎么搭的

Harness Engineering: Anatomy, Architecture, and Evolution of Coding Agents

Paul Barbaste、Tristan Darrigol、Germain Vu、Tom Wiltberger · arXiv:2609.00006 · 2026 年 7 月

12 个模块 概论约 40 分钟，精读另约 30 分钟 进阶 · 对着原文读
这篇论文在说什么

一个 Agent 是模型加上把它接到世界上的运行时。作者读了十一套生产编程 Agent 的源码，大约四百万行，不打分。他们发现没有人用通用编排框架，也没有人用向量去搜代码。2026 年上半年，这层外壳从工具变成了平台。

先把四个词分开

背景，不是论文结论。后面每句话都假定你分得清这些东西。

你已经见过这个场面

同一个模型，一个团队的 Agent 能连续改仓库，另一个跑三步就忘了任务，或者报错之后停在那里。论文认为先别换模型。

💡
这篇课的主语

外壳有个名字：harness。模型负责判断，harness 负责把判断变成对仓库的动作。

01

同一个模型，两种下场

论文要的不是谁分数高，而是外壳在源码里到底长什么样。

等式先于任何架构图

日常说法是：Agent 会自己改代码。论文把它拆成一件可以指认的东西。先记住意思，再看写法。

$$\text{Agent} = \text{Model} + \text{Harness}$$

模型提供判断。Harness 是除模型以外的全部：循环、工具、上下文、安全、编排、扩展。这句话 2026 年初从 LangChain 的工程系列里流行开。讽刺的是：词从那里来，语料里的运行时谁都没导入 LangChain。

$$\text{Harness} = \text{Loop} + \text{Tools} + \text{Context} + \text{Safety} + \text{Orchestration} + \text{Extensions}$$

七个子系统是分析维度，也是作者认为这件东西的解剖图。最小实现可以缩到「没有编排」。最大实现是平台：SDK、市场、治理。

$$\hat{t} = \left\lfloor \frac{1}{4} \sum_m |\mathrm{json}(m)| \right\rfloor$$

这不是物理定律。它是论文教学脚手架里的 token 估计：把消息编成 JSON，用字符数除以 4。过了阈值就摘要中间、留下系统消息和最近大约 30%。OpenCode 的真源码里也没有分词器，用的是同一类粗估计。

03

循环，以及文件怎么改

十一套都是 ReAct。反思和「协调者–工人」不是另外两种互斥循环。

三种脾气，叠在同一种循环上

9
迭代：动作，然后观察

组装提示，调用模型，执行工具，把观察追加回去。OpenHands 按资源锁并行。Claude Code 默认不并行，工具要自己声明并发安全。

1
反思形的主循环只有 Aider

改完跑语法、编译和 flake8，失败再叫模型，默认最多三次。它甚至没有工具调用循环，一轮在补全流结束时停下。

+
协调者–工人是叠加上去的

Claude Code 和 Codex 把研究、综合、实现、验证写成父 Agent 的调度。Hermes 要开配置才有。它不是第三种互斥的循环。

💡
停，也可以是一种设计

Hermes 如果改了代码却没有新的验证证据，会否决「我做完了」。OpenCode 见到三次完全相同的调用，不自动杀掉，而是通过权限问人。Pi 把「没有卡住检测」写成拒绝，不是忘了做。

九十行里，循环实际在做什么

下面是论文教学脚手架的形状，不是可复制的生产代码。点一行看它为什么在那里。

ALGORITHM INPUT: task, model, working directory context = READ AGENTS.md FROM root DOWN TO cwd messages = SYSTEM(context) + USER(task) WHILE TRUE IF turns OR cost OVER LIMIT THEN STOP IF tokens OVER THRESHOLD THEN SUMMARIZE middle, KEEP tail response = MODEL(messages, four tools) APPEND response IF no tool calls THEN RETURN text FOR EACH call: observation = RUN or CATCH as text APPEND observation END WHILE
WHY

任务、模型和当前目录。没有沙箱，没有第二个 Agent。

从根走到当前目录收集说明。这是十一套里反复出现的 Markdown 上下文。

系统提示靠近说明，用户任务在后。早期决定要留在容易被看见的位置。

线性 while。论文建议先写这个，等轮次策略堆到三件以上再拆成中间件。

便宜的上限。Mini-SWE-Agent 后来也加了步数、格式错误和墙钟。

压缩中间，留下最近一段原文。否则模型会忘掉刚刚的推理。

四只工具：bash、读、写、唯一子串替换。再多，是看见失败之后的事。

模型的话也是历史的一部分。下一步要看得见自己说过什么。

没有工具调用才算这一轮结束。停的条件是「不再行动」，不是「进程崩了」。

异常变成一条 ERROR 文本。循环还在，模型还能改。

观察必须回到消息里。否则模型以为工具没发生过。

下一轮带着完整痕迹继续。这就是外壳和「一次补全」的差别。

改文件的契约，比工具数量更决定准不准

严格
前沿模型这一侧

Claude Code、迁过去的 Mistral Vibe、Pi。旧文本必须在文件里恰好出现一次。对不上就报错，不偷偷改一个「差不多」的地方。

容忍
模型更杂时

Gemini CLI 从精确走到空白、正则、模糊，最后还可以用一次模型调用修匹配。OpenCode 和 Hermes 各有九段级联，源码注释写着彼此的继承。

方言
按模型族切换

Codex 用自己的 Begin/End Patch。OpenCode 对 GPT 家族换上这套，并拿掉字符串替换。编辑格式是模型的事，不是全局唯一答案。

别用
论文的反建议

模型对行号的漂移，比对上下文的漂移更严重。建议是在工具里处理匹配失败，而不是让模型报一个行号。

模型调用的替换工具抛了异常。按论文的最小循环，下一步应该发生什么？

04

谁来写记忆，谁来放行

压缩办法已经靠近。拉开差距的是写入记忆的人，以及 YOLO 底下还有没有地板。

压缩保住最近的话，记忆决定谁有权记下来

七套系统在窗口快满时做模型摘要。真正分叉的是跨会话的那一支笔。

Agent 写
最自主

后台抽出记忆，再由一个不能上网、只能本地写的沙箱子 Agent，对着 git 风格的差异做合并，放进 ~/.codex/memories/。

人来审
收件箱

四月还有 save_memory 工具。七月的系统提示说没有这个工具。抽取子 Agent 把补丁放进 .inbox/，人用 /memory 决定要不要留下。

有上限
为了缓存

两个有字数上限的 Markdown，会话中途可以写盘，但不能弄脏提示缓存。回忆对话用的是 SQLite 全文检索，不是向量。

回复前
先回忆再答

每次主回复之前先跑一个记忆子 Agent。它的向量检索默认开着，对象是对话，不是源码树。

05

两样大家都以为会有的东西

通用编排框架，和面向代码的向量检索。十一套源码里，两样都不在该在的位置上。

采用率，按十一套来算

条形是「十一套里有多少套这么做」，换算成百分比只是为了能看。0 不是测量误差。

源码里实际有的，和实际没有的

SKILL.md（9/11）
MCP（8/11）
ACP（6/11）
通用编排框架
向量检索源码

切到「用来读代码」时，这五行都是 0。Skill 和 MCP 是扩展，不是检索器。读代码靠的是 ripgrep、glob、tree-sitter 和自动发现的 Markdown。

为什么代码不适合先做成向量

1
结构已经是确定的

路径、语法树、语言服务器、类型。相似度复制不了「这个函数在这个文件的这一层」。

2
分钟级就会过期

论文的原话是：代码一分钟一分钟地变，预建的向量几乎一建好就旧了。

3
环境里已经有检索器

ripgrep、find、glob。再加一套向量库，是嵌入计算、漂移和维护，边际收益不稳定。

Effective Context Engineering for AI Agents
Rajasekaran 等，2025 年 9 月
偏向即时检索：用文件系统、收件箱、书签在需要时去取，而不是把整个语料背进索引。论文说十一套都走了这条实践。

「零框架」也有两处边界

0
运行时没有这些导入

LangChain、LangGraph、AutoGen、CrewAI、LlamaIndex、Pydantic AI、Genkit、Google ADK、Semantic Kernel。Gemini CLI 连谷歌自己的两套都不用。

边
OpenCode 用了 Vercel AI SDK

那是供应商抽象，不是编排框架。仓库里还有一个开关后面的自研客户端。作者猜这个依赖是过渡。

边
Aider 的 /help 可以装 llama-index

只检索 Aider 自己的文档，不进 Agent 循环。

🔎
他们怎么搜的

依赖清单加导入搜索，隔三个月又做了一遍，包括新加的三套和 meta-harness。没追踪动态导入和编译后的发行包。作者说，若有一条没被看见的路径用了 LangChain，他们会惊讶，但不会震惊。

这句话藏着哪一个没说完的边界？

「四百万行里零向量检索，没有一家把资料做成向量。」
06

外壳变成了平台

四月这还是假说。七月作者把它写成已经发生的事。然后他们划出不能推出的结论。

四个能在源码里指认的信号

1
Skill 是写给模型的程序

英文加 YAML 头。现在有注册表、供应链审查，以及会写 skill 的 Agent。

2
钩子成了扩展基底

四月还是 Claude Code 的特色。七月十一套里有九套。Codex 的事件名逐字沿用，并多了一个 PostCompact。

3
界面变成平台的界面

OpenCode 内嵌 HTTP 和生成的 SDK，终端、网页、IDE 都是客户端。OpenHands 把对话暴露成兼容 OpenAI 的端点：Agent 变成了一个模型。

4
上面又长出一层

Omnigent 把二十多家 harness 当成可替换部件。它补策略、沙箱和多设备会话，自己不实现编辑循环。

Building Effective Agents
Schluntz 与 Zhang，2024 年 12 月
警告框架会挡住提示和响应，让调试变难，建议从原始 SDK 调用开始。2026 年的源码审计显示，厂商旗舰都这么做了。论文说这可能是共同经验，也可能是指南影响了设计，或两者都有。他们没有访谈。

若你要新写一个，论文让你先不做的事

15
不要用通用框架当运行时

想要现成的，2026 年的「框架」是 harness SDK：Claude Agent SDK、openai-codex、OpenHands 的包。

16
不要为代码建向量索引

先在留出的任务上证明它胜过 ripgrep 加 tree-sitter，再考虑基础设施。

18
卡住检测不要过度设计

十几行的上限要有：连续格式错误、墙钟、三次相同调用就问人。五种场景的检测器是平台级投入。

10
九十行直接实现了十条

其余八条与它兼容，但没有被写进去。沙箱、多 Agent、skill 都在「量到失败再加」的那一侧。

作者自己不许你推出的结论

1
快照会过期

工具数量和版本钉按星期变。循环分类、七个子系统、两个缺席，到这一版还在。

2
没有统一评测

不能从这份解剖推出谁更会做题，也不能把九十行当成打过基准的模板。

3
样本不是整个市场

Copilot CLI、Cursor、Cline、Goose、Kiro、Antigravity 都不在这十一套里。

💡
竞争的单位变了

论文的收束句：这个领域的竞争单位不再是 Agent 循环，而是循环外面的生态表面。钩子、会话导入器、SDK、以及会托管别家 harness 的 ACP。

同事把论文末尾大约九十行的 Python 拷进生产仓库，说「十八条建议都在里面了」。哪一句更接近论文？

精读从限定语开始

概论把地图给过你了。从这里起，每句话只问三件事：它承诺什么，证据在哪，它拒绝什么。

对着 arXiv HTML 时，就用这三问

1
承诺

主语是谁，动词有多强。是「十一套都这样」，还是「到这一版还这样」。

2
证据

这句话靠源码、靠一张图，还是靠作者的猜想。搜导入和读一张图，不是同一种证据。

3
拒绝

紧挨着的限定语删掉之后，句子会变成另一篇论文。精读就是把那个限定语标回来。

📖

❝
§1

An agent is a model plus a harness. The model supplies the intelligence; the harness turns that intelligence into work.

加
第一分句是加法

Agent 等于模型加上 harness。不是「用外壳换掉模型」，也不是「外壳本身有智能」。

智
智能的位置在模型

supplies the intelligence。后面所有架构差异，论文都不拿来解释成「这个外壳更聪明」。

工
外壳把判断变成工作

turns that intelligence into work。工作是对仓库的动作、权限、恢复和停。这句话没说外壳能提高智力。

把说满的句子放回它丢掉的限定语

外壳从工具变成了平台
四百万行里零向量
没有任何框架
九十行实现了十八条

限定在 2026 年上半年的编程 harness，而且作者写成已经发生。不是所有 Agent，也不是永远。

拖放到这里

对象是读代码。对话记忆可以有嵌入。OpenClaw 的默认记忆就是向量加全文检索。

拖放到这里

缺的是运行时里的通用编排框架。OpenCode 的供应商 SDK、Aider 给自己文档用的检索，是边界。

拖放到这里

Listing 3 直接实现 10 条，并与另外 8 条兼容。沙箱、多 Agent、skill 没有写进去。

拖放到这里

笔记写：「Mini-SWE-Agent 大约一百行，成绩和大系统同一档，所以简单循环已经够用。」哪一步读法是对的？

08

把定义的两句读完

§2 的定义很短。精读是看它把哪些东西算进「除模型以外」，又把哪些近义词推出去。

everything except the model

❝
§2.1

The harness is everything except the model: the runtime that couples an LLM to the world.

冒号后面把 everything 收成一件东西：把语言模型接到世界上的运行时。作者采用的核心来自 Macedo，再用七个子系统把它拆开：循环、模型接入、工具、记忆与上下文、安全、编排、扩展。定义文献暗示过这些部分，生产源码里此前没有被这样落地。

💡
七个子系统旁边还有两块横切表面

界面层是人用的：终端、旗标、IDE 协议、HTTP、SDK。会话基底是多个子系统共用的：记录、持久化、恢复、分叉。平台化的论证，很大一部分落在界面层上，而不是落在「循环更精致」上。

这句定义推出去的四个近义词

1
不是脚手架本身

脚手架是结构代码。Harness 是嵌进产品、交出去的运行时。一百行可以是脚手架；带权限和插件的产品才是 harness。

2
不是导入的框架

框架是开发者 import 的库。Harness 是人在里面工作的运行时。论文说这条界在 2026 年从两边同时在溶解，但定义本身还保持这个方向。

3
不是评测 harness

SWE-bench 包住 Agent 去跑题。Agent harness 包住模型让它行动。同一个词，包裹方向相反。

4
不是编排器

编排器在上面协调别的 harness，自己没有编辑循环。Omnigent 是关于 harness 的证据，把它算进十一套是分类错误。

这句话把定义收窄成了什么？

「Harness 就是提示词模板，再加上一份工具列表。」

Mini-SWE-Agent 用大约一百行实现了全部七个子系统。精读时，这句证明允许你留下哪一个结论？

09

先核对「十一」和「三种循环」

§4 到 §6 最常见的误读，是把对照物算进样本，再把三种循环读成三选一。

样本那句话，主语要数全

四家厂商旗舰都在里面：Claude Code、Codex CLI、Gemini CLI，以及摘要里经常消失的 Mistral Vibe。开源一侧包括 OpenHands、Aider、Mini-SWE-Agent。快照钉在 2026 年 7 月能拿到的版本。

内
OpenClaw 在十一套里，但是离群点

它把自己写成个人助手网关，不是编程 Agent，没有原生改代码工具。放进来是为了检验「大家都在收敛」是不是只对编程 Agent 成立。Hermes 也是多通道网关，但自带编程工具，所以是普通成员。

外
Omnigent 不在十一套里

它把 harness 当成可替换部件，自己没有编辑循环。和十一套并列打七个子系统的分，是分类错误。

旧
纵向样本是四月那八套

七月才加入的 Hermes、Pi、OpenCode 不在「同一仓库钉两次」的差异里。三条旧观察后来被改写，改的是这八套的重读，不是这三套的前后对比。

⚠
Claude Code 的源码不是七月二进制

论文用的是 2026 年 3 月流传的非官方源码。七月发行二进制是 2.1.206，正文写明二进制可能已经不同。读到 Claude Code 的细节时，先记住这个版本差。

循环那句：三种形状，不是三选一

主体
动作–观察

九套的主循环是迭代式：组装提示，调用模型，执行工具，把观察追加回去。差别在并发、状态放在哪、什么叫做停。

唯一
反思形主循环

Aider 改完跑语法、编译和 flake8，失败再叫一次模型，默认最多三次。它是唯一把反思放进主循环的系统，不是第十一套里的普遍形态。

叠加
不是第三类

协调者–工作者叠在迭代循环上。Claude Code 和 Codex 里是规定好的，Hermes 要开配置。删掉「叠加」两个字，分类就错了。

误读
三选一

「每套系统恰好属于一种循环」不是论文的句子。十一套都是 ReAct 的变体。协调者可以和动作–观察同时存在。

有人说：「论文比较了 Hermes 从四月到七月的源码差异。」这句错在哪？

10

四句很容易读滑的话

§8 到 §12。工具数量、层数、沙箱和协议，每句都有一个不在字面上的边界。

改文件的契约，比工具个数更决定准不准

个数本身说明不了能力：Mini-SWE-Agent 把一切塞进一次 shell；Claude Code 列出 43 个工具；Pi 造 7 个、默认露出 4 个；Hermes 注册 69 个再用工具集过滤；OpenClaw 的 109 以上包含媒体和频道，它本来就不是代码编辑器。

论文另有一处勘误，适合当作精读练习。四月稿说旧的模糊匹配器会把模糊编辑应用到文件上。复审发现它只在报错里提示最接近的匹配，并没有真的改文件。读旧笔记时，先问这句是四月的误记，还是七月的正文。

「三层」和「四层」不在同一种文本里

图
Claude Code 的三层

常被说成「三层安全」。这个说法主要活在图 5。正文没有给这三层起名。精读时不要从散文里补出三个专名。

文
Codex 的四层

四层在正文里有名字：Starlark 执行策略（四月误写成 TOML）、生命周期钩子、Guardian 审查模型、原生操作系统沙箱。钩子事件名沿用 Claude Code，并多了 PostCompact。

🔒
沙箱不是规模的函数

四月看起来像「越大越有跨平台沙箱」。七月这条相关破了：Hermes 和 OpenCode 都很大，却没有操作系统级隔离。真正做原生沙箱的 Codex 和 Gemini CLI，是数千行的投入。Pi 把「不做半吊子的进程内沙箱」写成安全论点，因为那会被误认成边界。

协议那句：skill、MCP、ACP 各算各的

9
Skill 是 9/11，不是全员

不做的是 Aider 和 Mini-SWE-Agent。四月 skill 和 MCP 打平。打破平局的是 Pi：要 skill，不要 MCP。MCP 是 8/11。

3
ACP 有第三个角色

六个系统把它当正式部件。除了编辑器驱动本地 Agent，还有「把别家 harness 当成可替换的大脑」。OpenHands 可以把一步委托给 Claude Code、Codex 或 Gemini CLI。A2A 网格仍然只有 Gemini CLI。

内
子 Agent 大多留在进程内

多 Agent 收敛成层级，不是一张对等网格。读到「它们组成了 Agent 网络」时，先回到这句。

同事要你「按论文正文，列出 Claude Code 安全三层的名字」。哪一种回答符合精读？

11

把限定语读回去

§13 到结尾。两个缺席、三条被改写的旧观察、以及作者不许你推出的结论。

两个缺席，各带自己的因为

❝
§13.2

Code changes minute to minute, so pre-indexed embeddings are stale almost by construction.

这句解释的是代码检索。代码分钟级在变，预先做好的嵌入几乎一建好就过期。替代品是 ripgrep、glob、tree-sitter 和语言服务器。它没有说嵌入不能用来回忆对话。

框
框架缺席查的是清单和导入

做了两轮，包括后加的系统和 meta-harness。没追踪动态导入和编译后的发行包。作者说，若有一条没被看见的路径用了 LangChain，他们会惊讶，但不会震惊。

边
两处不能删的边界

OpenCode 用 Vercel AI SDK 做模型接入，不是编排。Aider 的 /help 可以可选安装 llama-index，只检索自己的文档。Hermes 里仅有的 LangChain 字符串，出现在教用户用向量库的 skill 文档里。

史
历史收场不是「他们落后了」

§14.2 的句子是：harness 没有采纳那些框架，它们取代了框架，并且自己变成了可以导入的库。

四月有三句，七月就地改了

1
耦合二分法

不是「只有厂商能做缓存和按模型写的提示」。多供应商系统可以用集中的条件代码买到其中一部分。只有服务端跟着模型发布改提示、客户端不用更新，还留在厂商自己那里。

2
规模意味着沙箱

这条相关破了。Hermes 和 OpenCode 是很大、但没有操作系统级隔离的反例。

3
协议只有两个角色

ACP 长出第三种用法：harness 托管别家 harness。A2A 网格仍然只有 Gemini CLI，这个「只有」没有被改掉。

💡
会过期的，和暂时还在的

工具数量、功能格子、版本钉按星期变。循环分类、七个子系统、两个缺席，到这一版还立得住。对着今天的仓库精读时，先对结构，再对某个文件还在不在。

收束句也不要读宽

❝
观察 12，§14.5

The competitive unit of the field is no longer the agent loop; it is the ecosystem surface around it.

竞争的单位从循环挪到了循环外面的生态表面：钩子、会话导入器、SDK、会托管别家 harness 的 ACP。这句没说循环对正确性不再重要，也没说谁的基准更高。Listing 3 仍然是教学脚手架：直接实现 10 条建议，兼容其余 8 条，shell=True，没有沙箱，用字符数估计 token，没有跑过基准。

这句转述把收束句推到了哪？

「论文证明循环已经不重要，接下来只做插件市场就行。」
