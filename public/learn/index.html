Harness Engineering：编程 Agent 的外壳是怎么搭的

Harness Engineering: Anatomy, Architecture, and Evolution of Coding Agents

Paul Barbaste、Tristan Darrigol、Germain Vu、Tom Wiltberger · arXiv:2609.00006 · 2026 年 7 月

7 个模块 约 40 分钟 进阶 · 写过 Agent 的人
这篇论文在说什么

一个 Agent 是模型加上把它接到世界上的运行时。作者读了十一套生产编程 Agent 的源码，大约四百万行，不打分。他们发现没有人用通用编排框架，也没有人用向量去搜代码。2026 年上半年，这层外壳从工具变成了平台。

先把四个词分开

背景，不是论文结论。后面每句话都假定你分得清这些东西。

你已经见过这个场面

同一个模型，一个团队的 Agent 能连续改仓库，另一个跑三步就忘了任务，或者报错之后停在那里。论文认为先别换模型。

💡
这篇课的主语

外壳有个名字：harness。模型负责判断，harness 负责把判断变成对仓库的动作。

01

同一个模型，两种下场

论文要的不是谁分数高，而是外壳在源码里到底长什么样。

等式先于任何架构图

日常说法是：Agent 会自己改代码。论文把它拆成一件可以指认的东西。先记住意思，再看写法。

$$\text{Agent} = \text{Model} + \text{Harness}$$

模型提供判断。Harness 是除模型以外的全部：循环、工具、上下文、安全、编排、扩展。这句话 2026 年初从 LangChain 的工程系列里流行开。讽刺的是：词从那里来，语料里的运行时谁都没导入 LangChain。

$$\text{Harness} = \text{Loop} + \text{Tools} + \text{Context} + \text{Safety} + \text{Orchestration} + \text{Extensions}$$

七个子系统是分析维度，也是作者认为这件东西的解剖图。最小实现可以缩到「没有编排」。最大实现是平台：SDK、市场、治理。

$$\hat{t} = \left\lfloor \frac{1}{4} \sum_m |\mathrm{json}(m)| \right\rfloor$$

这不是物理定律。它是论文教学脚手架里的 token 估计：把消息编成 JSON，用字符数除以 4。过了阈值就摘要中间、留下系统消息和最近大约 30%。OpenCode 的真源码里也没有分词器，用的是同一类粗估计。

03

循环，以及文件怎么改

十一套都是 ReAct。反思和「协调者–工人」不是另外两种互斥循环。

三种脾气，叠在同一种循环上

9
迭代：动作，然后观察

组装提示，调用模型，执行工具，把观察追加回去。OpenHands 按资源锁并行。Claude Code 默认不并行，工具要自己声明并发安全。

1
反思形的主循环只有 Aider

改完跑语法、编译和 flake8，失败再叫模型，默认最多三次。它甚至没有工具调用循环，一轮在补全流结束时停下。

+
协调者–工人是叠加上去的

Claude Code 和 Codex 把研究、综合、实现、验证写成父 Agent 的调度。Hermes 要开配置才有。它不是第三种互斥的循环。

💡
停，也可以是一种设计

Hermes 如果改了代码却没有新的验证证据，会否决「我做完了」。OpenCode 见到三次完全相同的调用，不自动杀掉，而是通过权限问人。Pi 把「没有卡住检测」写成拒绝，不是忘了做。

九十行里，循环实际在做什么

下面是论文教学脚手架的形状，不是可复制的生产代码。点一行看它为什么在那里。

ALGORITHM INPUT: task, model, working directory context = READ AGENTS.md FROM root DOWN TO cwd messages = SYSTEM(context) + USER(task) WHILE TRUE IF turns OR cost OVER LIMIT THEN STOP IF tokens OVER THRESHOLD THEN SUMMARIZE middle, KEEP tail response = MODEL(messages, four tools) APPEND response IF no tool calls THEN RETURN text FOR EACH call: observation = RUN or CATCH as text APPEND observation END WHILE
WHY

任务、模型和当前目录。没有沙箱，没有第二个 Agent。

从根走到当前目录收集说明。这是十一套里反复出现的 Markdown 上下文。

系统提示靠近说明，用户任务在后。早期决定要留在容易被看见的位置。

线性 while。论文建议先写这个，等轮次策略堆到三件以上再拆成中间件。

便宜的上限。Mini-SWE-Agent 后来也加了步数、格式错误和墙钟。

压缩中间，留下最近一段原文。否则模型会忘掉刚刚的推理。

四只工具：bash、读、写、唯一子串替换。再多，是看见失败之后的事。

模型的话也是历史的一部分。下一步要看得见自己说过什么。

没有工具调用才算这一轮结束。停的条件是「不再行动」，不是「进程崩了」。

异常变成一条 ERROR 文本。循环还在，模型还能改。

观察必须回到消息里。否则模型以为工具没发生过。

下一轮带着完整痕迹继续。这就是外壳和「一次补全」的差别。

改文件的契约，比工具数量更决定准不准

严格
前沿模型这一侧

Claude Code、迁过去的 Mistral Vibe、Pi。旧文本必须在文件里恰好出现一次。对不上就报错，不偷偷改一个「差不多」的地方。

容忍
模型更杂时

Gemini CLI 从精确走到空白、正则、模糊，最后还可以用一次模型调用修匹配。OpenCode 和 Hermes 各有九段级联，源码注释写着彼此的继承。

方言
按模型族切换

Codex 用自己的 Begin/End Patch。OpenCode 对 GPT 家族换上这套，并拿掉字符串替换。编辑格式是模型的事，不是全局唯一答案。

别用
论文的反建议

模型对行号的漂移，比对上下文的漂移更严重。建议是在工具里处理匹配失败，而不是让模型报一个行号。

模型调用的替换工具抛了异常。按论文的最小循环，下一步应该发生什么？

04

谁来写记忆，谁来放行

压缩办法已经靠近。拉开差距的是写入记忆的人，以及 YOLO 底下还有没有地板。

压缩保住最近的话，记忆决定谁有权记下来

七套系统在窗口快满时做模型摘要。真正分叉的是跨会话的那一支笔。

Agent 写
最自主

后台抽出记忆，再由一个不能上网、只能本地写的沙箱子 Agent，对着 git 风格的差异做合并，放进 ~/.codex/memories/。

人来审
收件箱

四月还有 save_memory 工具。七月的系统提示说没有这个工具。抽取子 Agent 把补丁放进 .inbox/，人用 /memory 决定要不要留下。

有上限
为了缓存

两个有字数上限的 Markdown，会话中途可以写盘，但不能弄脏提示缓存。回忆对话用的是 SQLite 全文检索，不是向量。

回复前
先回忆再答

每次主回复之前先跑一个记忆子 Agent。它的向量检索默认开着，对象是对话，不是源码树。

05

两样大家都以为会有的东西

通用编排框架，和面向代码的向量检索。十一套源码里，两样都不在该在的位置上。

采用率，按十一套来算

条形是「十一套里有多少套这么做」，换算成百分比只是为了能看。0 不是测量误差。

源码里实际有的，和实际没有的

SKILL.md（9/11）
MCP（8/11）
ACP（6/11）
通用编排框架
向量检索源码

切到「用来读代码」时，这五行都是 0。Skill 和 MCP 是扩展，不是检索器。读代码靠的是 ripgrep、glob、tree-sitter 和自动发现的 Markdown。

为什么代码不适合先做成向量

1
结构已经是确定的

路径、语法树、语言服务器、类型。相似度复制不了「这个函数在这个文件的这一层」。

2
分钟级就会过期

论文的原话是：代码一分钟一分钟地变，预建的向量几乎一建好就旧了。

3
环境里已经有检索器

ripgrep、find、glob。再加一套向量库，是嵌入计算、漂移和维护，边际收益不稳定。

Effective Context Engineering for AI Agents
Rajasekaran 等，2025 年 9 月
偏向即时检索：用文件系统、收件箱、书签在需要时去取，而不是把整个语料背进索引。论文说十一套都走了这条实践。

「零框架」也有两处边界

0
运行时没有这些导入

LangChain、LangGraph、AutoGen、CrewAI、LlamaIndex、Pydantic AI、Genkit、Google ADK、Semantic Kernel。Gemini CLI 连谷歌自己的两套都不用。

边
OpenCode 用了 Vercel AI SDK

那是供应商抽象，不是编排框架。仓库里还有一个开关后面的自研客户端。作者猜这个依赖是过渡。

边
Aider 的 /help 可以装 llama-index

只检索 Aider 自己的文档，不进 Agent 循环。

🔎
他们怎么搜的

依赖清单加导入搜索，隔三个月又做了一遍，包括新加的三套和 meta-harness。没追踪动态导入和编译后的发行包。作者说，若有一条没被看见的路径用了 LangChain，他们会惊讶，但不会震惊。

这句话藏着哪一个没说完的边界？

「四百万行里零向量检索，没有一家把资料做成向量。」
06

外壳变成了平台

四月这还是假说。七月作者把它写成已经发生的事。然后他们划出不能推出的结论。

四个能在源码里指认的信号

1
Skill 是写给模型的程序

英文加 YAML 头。现在有注册表、供应链审查，以及会写 skill 的 Agent。

2
钩子成了扩展基底

四月还是 Claude Code 的特色。七月十一套里有九套。Codex 的事件名逐字沿用，并多了一个 PostCompact。

3
界面变成平台的界面

OpenCode 内嵌 HTTP 和生成的 SDK，终端、网页、IDE 都是客户端。OpenHands 把对话暴露成兼容 OpenAI 的端点：Agent 变成了一个模型。

4
上面又长出一层

Omnigent 把二十多家 harness 当成可替换部件。它补策略、沙箱和多设备会话，自己不实现编辑循环。

Building Effective Agents
Schluntz 与 Zhang，2024 年 12 月
警告框架会挡住提示和响应，让调试变难，建议从原始 SDK 调用开始。2026 年的源码审计显示，厂商旗舰都这么做了。论文说这可能是共同经验，也可能是指南影响了设计，或两者都有。他们没有访谈。

若你要新写一个，论文让你先不做的事

15
不要用通用框架当运行时

想要现成的，2026 年的「框架」是 harness SDK：Claude Agent SDK、openai-codex、OpenHands 的包。

16
不要为代码建向量索引

先在留出的任务上证明它胜过 ripgrep 加 tree-sitter，再考虑基础设施。

18
卡住检测不要过度设计

十几行的上限要有：连续格式错误、墙钟、三次相同调用就问人。五种场景的检测器是平台级投入。

10
九十行直接实现了十条

其余八条与它兼容，但没有被写进去。沙箱、多 Agent、skill 都在「量到失败再加」的那一侧。

作者自己不许你推出的结论

1
快照会过期

工具数量和版本钉按星期变。循环分类、七个子系统、两个缺席，到这一版还在。

2
没有统一评测

不能从这份解剖推出谁更会做题，也不能把九十行当成打过基准的模板。

3
样本不是整个市场

Copilot CLI、Cursor、Cline、Goose、Kiro、Antigravity 都不在这十一套里。

💡
竞争的单位变了

论文的收束句：这个领域的竞争单位不再是 Agent 循环，而是循环外面的生态表面。钩子、会话导入器、SDK、以及会托管别家 harness 的 ACP。

同事把论文末尾大约九十行的 Python 拷进生产仓库，说「十八条建议都在里面了」。哪一句更接近论文？
