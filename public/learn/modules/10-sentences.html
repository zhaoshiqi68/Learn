四句很容易读滑的话

§8 到 §12。工具数量、层数、沙箱和协议，每句都有一个不在字面上的边界。

改文件的契约，比工具个数更决定准不准

个数本身说明不了能力：Mini-SWE-Agent 把一切塞进一次 shell；Claude Code 列出 43 个工具；Pi 造 7 个、默认露出 4 个；Hermes 注册 69 个再用工具集过滤；OpenClaw 的 109 以上包含媒体和频道，它本来就不是代码编辑器。

论文另有一处勘误，适合当作精读练习。四月稿说旧的模糊匹配器会把模糊编辑应用到文件上。复审发现它只在报错里提示最接近的匹配，并没有真的改文件。读旧笔记时，先问这句是四月的误记，还是七月的正文。

「三层」和「四层」不在同一种文本里

图
Claude Code 的三层

常被说成「三层安全」。这个说法主要活在图 5。正文没有给这三层起名。精读时不要从散文里补出三个专名。

文
Codex 的四层

四层在正文里有名字：Starlark 执行策略（四月误写成 TOML）、生命周期钩子、Guardian 审查模型、原生操作系统沙箱。钩子事件名沿用 Claude Code，并多了 PostCompact。

🔒
沙箱不是规模的函数

四月看起来像「越大越有跨平台沙箱」。七月这条相关破了：Hermes 和 OpenCode 都很大，却没有操作系统级隔离。真正做原生沙箱的 Codex 和 Gemini CLI，是数千行的投入。Pi 把「不做半吊子的进程内沙箱」写成安全论点，因为那会被误认成边界。

协议那句：skill、MCP、ACP 各算各的

9
Skill 是 9/11，不是全员

不做的是 Aider 和 Mini-SWE-Agent。四月 skill 和 MCP 打平。打破平局的是 Pi：要 skill，不要 MCP。MCP 是 8/11。

3
ACP 有第三个角色

六个系统把它当正式部件。除了编辑器驱动本地 Agent，还有「把别家 harness 当成可替换的大脑」。OpenHands 可以把一步委托给 Claude Code、Codex 或 Gemini CLI。A2A 网格仍然只有 Gemini CLI。

子 Agent 大多留在进程内

多 Agent 收敛成层级，不是一张对等网格。读到「它们组成了 Agent 网络」时，先回到这句。
