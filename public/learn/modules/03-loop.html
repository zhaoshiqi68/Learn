循环，以及文件怎么改

十一套都是 ReAct。反思和「协调者–工人」不是另外两种互斥循环。

三种脾气，叠在同一种循环上

9
迭代：动作，然后观察

组装提示，调用模型，执行工具，把观察追加回去。OpenHands 按资源锁并行。Claude Code 默认不并行，工具要自己声明并发安全。

1
反思形的主循环只有 Aider

改完跑语法、编译和 flake8，失败再叫模型，默认最多三次。它甚至没有工具调用循环，一轮在补全流结束时停下。

+
协调者–工人是叠加上去的

Claude Code 和 Codex 把研究、综合、实现、验证写成父 Agent 的调度。Hermes 要开配置才有。它不是第三种互斥的循环。

💡
停，也可以是一种设计

Hermes 如果改了代码却没有新的验证证据，会否决「我做完了」。OpenCode 见到三次完全相同的调用，不自动杀掉，而是通过权限问人。Pi 把「没有卡住检测」写成拒绝，不是忘了做。

九十行里，循环实际在做什么

下面是论文教学脚手架的形状，不是可复制的生产代码。点一行看它为什么在那里。

ALGORITHM INPUT: task, model, working directory context = READ AGENTS.md FROM root DOWN TO cwd messages = SYSTEM(context) + USER(task) WHILE TRUE IF turns OR cost OVER LIMIT THEN STOP IF tokens OVER THRESHOLD THEN SUMMARIZE middle, KEEP tail response = MODEL(messages, four tools) APPEND response IF no tool calls THEN RETURN text FOR EACH call: observation = RUN or CATCH as text APPEND observation END WHILE
WHY

任务、模型和当前目录。没有沙箱，没有第二个 Agent。

从根走到当前目录收集说明。这是十一套里反复出现的 Markdown 上下文。

系统提示靠近说明，用户任务在后。早期决定要留在容易被看见的位置。

线性 while。论文建议先写这个，等轮次策略堆到三件以上再拆成中间件。

便宜的上限。Mini-SWE-Agent 后来也加了步数、格式错误和墙钟。

压缩中间，留下最近一段原文。否则模型会忘掉刚刚的推理。

四只工具：bash、读、写、唯一子串替换。再多，是看见失败之后的事。

模型的话也是历史的一部分。下一步要看得见自己说过什么。

没有工具调用才算这一轮结束。停的条件是「不再行动」，不是「进程崩了」。

异常变成一条 ERROR 文本。循环还在，模型还能改。

观察必须回到消息里。否则模型以为工具没发生过。

下一轮带着完整痕迹继续。这就是外壳和「一次补全」的差别。

改文件的契约，比工具数量更决定准不准

严格
前沿模型这一侧

Claude Code、迁过去的 Mistral Vibe、Pi。旧文本必须在文件里恰好出现一次。对不上就报错，不偷偷改一个「差不多」的地方。

容忍
模型更杂时

Gemini CLI 从精确走到空白、正则、模糊，最后还可以用一次模型调用修匹配。OpenCode 和 Hermes 各有九段级联，源码注释写着彼此的继承。

方言
按模型族切换

Codex 用自己的 Begin/End Patch。OpenCode 对 GPT 家族换上这套，并拿掉字符串替换。编辑格式是模型的事，不是全局唯一答案。

别用
论文的反建议

模型对行号的漂移，比对上下文的漂移更严重。建议是在工具里处理匹配失败，而不是让模型报一个行号。

模型调用的替换工具抛了异常。按论文的最小循环，下一步应该发生什么？
