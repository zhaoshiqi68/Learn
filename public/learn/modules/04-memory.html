谁来写记忆，谁来放行

压缩办法已经靠近。拉开差距的是写入记忆的人，以及 YOLO 底下还有没有地板。

压缩保住最近的话，记忆决定谁有权记下来

七套系统在窗口快满时做模型摘要。真正分叉的是跨会话的那一支笔。

Agent 写
最自主

后台抽出记忆，再由一个不能上网、只能本地写的沙箱子 Agent，对着 git 风格的差异做合并，放进 ~/.codex/memories/。

人来审
收件箱

四月还有 save_memory 工具。七月的系统提示说没有这个工具。抽取子 Agent 把补丁放进 .inbox/，人用 /memory 决定要不要留下。

有上限
为了缓存

两个有字数上限的 Markdown，会话中途可以写盘，但不能弄脏提示缓存。回忆对话用的是 SQLite 全文检索，不是向量。

回复前
先回忆再答

每次主回复之前先跑一个记忆子 Agent。它的向量检索默认开着，对象是对话，不是源码树。

⚠
代码大，不等于有沙箱

七月改写了四月的相关。Hermes 和 OpenCode 都很大，操作系统级隔离是零。Pi 认为半吊子的进程内沙箱会被人误认成边界，所以干脆不做。

扩展：skill 比 MCP 多一套

MCP

我连接 Slack、数据库和内部 API。八套系统把我当成外部进程的标准口。
