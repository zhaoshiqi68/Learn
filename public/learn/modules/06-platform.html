外壳变成了平台

四月这还是假说。七月作者把它写成已经发生的事。然后他们划出不能推出的结论。

四个能在源码里指认的信号

1
Skill 是写给模型的程序

英文加 YAML 头。现在有注册表、供应链审查，以及会写 skill 的 Agent。

2
钩子成了扩展基底

四月还是 Claude Code 的特色。七月十一套里有九套。Codex 的事件名逐字沿用，并多了一个 PostCompact。

3
界面变成平台的界面

OpenCode 内嵌 HTTP 和生成的 SDK，终端、网页、IDE 都是客户端。OpenHands 把对话暴露成兼容 OpenAI 的端点：Agent 变成了一个模型。

4
上面又长出一层

Omnigent 把二十多家 harness 当成可替换部件。它补策略、沙箱和多设备会话，自己不实现编辑循环。

Building Effective Agents
Schluntz 与 Zhang，2024 年 12 月
警告框架会挡住提示和响应，让调试变难，建议从原始 SDK 调用开始。2026 年的源码审计显示，厂商旗舰都这么做了。论文说这可能是共同经验，也可能是指南影响了设计，或两者都有。他们没有访谈。

若你要新写一个，论文让你先不做的事

15
不要用通用框架当运行时

想要现成的，2026 年的「框架」是 harness SDK：Claude Agent SDK、openai-codex、OpenHands 的包。

16
不要为代码建向量索引

先在留出的任务上证明它胜过 ripgrep 加 tree-sitter，再考虑基础设施。

18
卡住检测不要过度设计

十几行的上限要有：连续格式错误、墙钟、三次相同调用就问人。五种场景的检测器是平台级投入。

10
九十行直接实现了十条

其余八条与它兼容，但没有被写进去。沙箱、多 Agent、skill 都在「量到失败再加」的那一侧。

作者自己不许你推出的结论

1
快照会过期

工具数量和版本钉按星期变。循环分类、七个子系统、两个缺席，到这一版还在。

2
没有统一评测

不能从这份解剖推出谁更会做题，也不能把九十行当成打过基准的模板。

3
样本不是整个市场

Copilot CLI、Cursor、Cline、Goose、Kiro、Antigravity 都不在这十一套里。

💡
竞争的单位变了

论文的收束句：这个领域的竞争单位不再是 Agent 循环，而是循环外面的生态表面。钩子、会话导入器、SDK、以及会托管别家 harness 的 ACP。

同事把论文末尾大约九十行的 Python 拷进生产仓库，说「十八条建议都在里面了」。哪一句更接近论文？
